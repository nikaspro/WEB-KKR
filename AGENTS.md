# AGENTS.md

Рабочий контекст проекта для Claude. Лежит в знаниях проекта и читается как правила поведения, а не как справка. Второго источника истины нет: всё, что нужно знать про сайт, живёт в этом файле и в коде.

Проект — лендинг «Путешествовать — легко»: **статика, Vite, ванильный JS, чистый CSS, GSAP из npm**. Одна скролл-сцена на одну страницу. Сцена в `src/scene/`, экран приложения в `src/app-screen/`, стили в `src/styles/`, медиа и шрифты в `public/`. Имя модуля по фазе сцены, не по эффекту.

**Три приоритета, важнее любой красоты: не усложнять, не утяжелять, оптимизировать имеющееся.** Спорный случай решается в пользу простоты, а не полноты.

Если правила конфликтуют между собой, порядок такой: визуальный результат сцены не меняется, потом бюджет, потом простота. Когда одно нельзя выполнить, не нарушив другое, — не решай сам, спроси.

## Как отвечать

- Кратко, по делу, без вступлений и пересказа задачи. Развёрнуто только по прямой просьбе.
- Сначала готовое, потом своё: перед новым решением проверь, нет ли готового в `src/scene/`, в репозитории и в скиллах.
- Файл сразу, обсуждение потом. Итерации идут по визуалу.
- Патчи, не переписывания: точечный `str_replace`, для больших правок Python heredoc с `assert count==1`. После каждой значимой правки проверка синтаксиса и баланса скобок, только потом отдаёшь файл.
- Короткая реплика («не», «бесит», «чутка») это промах или микроправка, без разжёвывания.
- «Реши за меня» значит выбираешь без хеджирования.
- После задачи: что изменилось, как проверить, что не верифицировал, сколько весит JS и критический путь, и сколько весит страница целиком.

## Эталон анимации

Оптимизируется **цена** анимации, а не сама анимация. Визуальный результат — инвариант: то, что видит пользователь на нормальном устройстве, после любой оптимизации остаётся прежним. Главный враг ощущения от сцены не тяжёлый код, а дёрганье: та же сцена без потерянных кадров ощущается лучше, а не беднее. Поэтому оптимизация и «кайф» тянут в одну сторону, а не в разные.

### Чем зафиксирован

`docs/baseline/` — эталон текущей сцены. Обновляется только вместе с осознанным изменением хореографии, в том же коммите:

- `scroll.mp4` — полная прокрутка страницы: фиксированный viewport, DPR 2, та же длительность прокрутки
- `trace.json` — performance-трейс DevTools за ту же прокрутку
- `animation.md` — таблица по каждому твину: элемент, свойство, длительность, easing, задержка, окно фазы. Генерируется из `src/scene/phases.js`, руками не правится

Правка, затрагивающая сцену, без сравнения с эталоном не принимается: «стало как было» без артефакта непроверяемо.

### Можно без согласования — результат пиксельно идентичен

- то же движение через `transform` и `opacity` вместо `width`, `height`, `top`, `left`, `margin`
- одна rAF-петля вместо нескольких; чтение layout один раз за кадр, без чередования read → write
- пассивные слушатели скролла; `will-change` по фазе со снятием после
- ленивая инициализация фазы при подходе к окну вместо работы на старте
- `content-visibility: auto` на секциях вне экрана
- только используемые модули GSAP
- картинки, шрифты, мёртвый CSS и JS — к хореографии не относятся вообще

### Нужно согласование владельца

Длительности, кривые easing, stagger, точки срабатывания, число одновременно анимируемых элементов, замена GSAP на нативные средства. Показать два варианта рядом, решает владелец, не исполнитель.

## Бюджет

Байты считаем **transferred (brotli quality 11)** по собранному `dist/`, как их видит устройство. raw пишем в отчёт справочно. Медиа и `woff2` уже сжаты, для них transferred примерно равно raw.

Лимиты по типам, потому что байты неравноценны: JS нужно скачать, распарсить, скомпилировать и исполнить на главном потоке, а картинка декодируется вне него. Единый общий лимит это стирает: можно уложиться в 900 КБ и получить неотзывчивую страницу.

| ресурс | лимит transferred | почему так |
|---|---|---|
| HTML | 15 КБ (raw ≤ 60) | больше значит дубли в разметке |
| CSS | 40 КБ, инлайном ≤ 10 КБ | инлайн блокирует отрисовку, остальное нет |
| **JS** | **≤ 100 КБ** | самая дорогая строка и главный источник фризов |
| шрифты | ≤ 100 КБ, 2 файла `woff2`, сабсет | частая причина провала первого экрана |
| картинка первого экрана | ≤ 150 КБ | один hero в WebP |
| видео | ≤ 400 КБ за файл | без лимита в байтах «640px и 10 секунд» это и 200 КБ, и 3 МБ |
| критический путь | ≤ 300 КБ | состав ниже, это не сумма строк выше |
| вся страница | ≤ 900 КБ | страховка от «залили фото с телефона на 4 МБ», а не цель |

Критический путь — только то, что стоит между запросом и первой отрисовкой: HTML + инлайновый CSS + шрифты первого экрана + LCP-картинка + любой JS без `defer`. Отложенный JS, остальной CSS и ленивые картинки в него не входят. Штатно выходит 15 + 10 + 100 + 150 = 275 КБ при потолке 300. Складывать все строки таблицы в одну сумму (получится 405) — ошибка: типовые лимиты и критический путь считают разные вещи.

Остальные картинки лениво, в пределах общего потолка. Арифметика связки: Slow 3G это примерно 50 КБ/с, Slow 4G около 200 КБ/с, значит LCP 2.0s на 4G достижим только при критическом пути в районе 300 КБ. Скорость держат лимит на JS и лимит критического пути, общий вес это дисциплина по картинкам.

Гейт `npm run budget` (голый Node, `zlib` встроенный, ноль зависимостей, падает с кодом 1) бежит по `dist/` после `npm run build`, в CI на каждом PR, а не только руками. Кроме весов проверяет:

- сторонние origin в отдаче: ноль. Белый список в `budget.json`, XML-неймспейсы не считаются
- CLS: `width` и `height` обязательны на каждом `<img>` и `<video>`
- ленивость: `loading="lazy"` на всех картинках кроме `eagerAllow`, `preload="none"` на видео
- шрифты: только `.woff2`, не больше двух файлов
- в отдаче нет `data:` длиннее 2 КБ, в собранном CSS нет статических `will-change`

Полевые метрики отдельной командой и отдельным решением по установке Lighthouse (сотни мегабайт `node_modules`):

- LCP ≤ 2.0s на пресете «Slow 4G» и ≤ 3.5s на «Slow 3G», в обоих CPU x4. Медиана из 5 прогонов, одиночный не считается
- TBT ≤ 200 мс, длинных задач дольше 50 мс не больше двух
- CLS ≤ 0.1. Проверка `width`/`height` в гейте закрывает только картинки; шрифты со `swap`, поздние вставки и анимация layout-свойств дают сдвиги мимо неё

Кадровый бюджет не автоматизируем: в CI он врёт. 60 fps на скролле при DPR 2 и ≤ 4 мс скриптом на кадр проверяем трейсом DevTools перед мержем и прикладываем скриншот. Красный гейт, который врёт, рано или поздно отключают.

Превышение закрывается сокращением работы, а не поднятием лимита: **режем фазу, а не покупаем железо.** Лимиты в `budget.json` меняет только владелец.

Цифры до и после в ответе. «Потом померим» не считается.

## Простота

- Ни React, ни Vue, ни Svelte, ни сборки TypeScript, ни SSR, ни CMS, ни роутера. Сцена — DOM и трансформы.
- Новая зависимость только с обоснованием и замером веса до и после. GSAP — единственная рантайм-зависимость: ядро плюс ScrollTrigger это порядка 36 КБ gzip, больше трети бюджета JS, и это известная учтённая величина. Любой другой плагин GSAP проходит ту же процедуру, что новая зависимость.
- Никаких шейдеров, Three.js, WebGL и физических движков.
- Второй версии страницы под мобильные нет. Есть один флаг `LITE` и ветки внутри тех же модулей.
- Кастомный эффект только если готовое не подошло, и тогда с фолбэком. Фолбэк по feature detection, никогда по User-Agent.
- Сборка TypeScript не вводится, но `// @ts-check` и типы в JSDoc включены: Vite уже в проекте, цена нулевая и в байтах, и в настройке, а опечатки в селекторах и обращения к `null` ловятся до браузера.

## Вес

- Ассеты файлами, не base64. Ни одного `data:` длиннее 2 КБ в исходниках.
- Видео: h264, ширина ≤ 640, ≤ 10 секунд, ≤ 400 КБ, `poster`, `preload="none"`, старт по попаданию в кадр. На ширине < 900px вместо видео статичный WebP: декода нет вообще.
- Картинки WebP, ширина по фактическому размеру в макете, `loading="lazy"` для всего вне первого экрана. Для hero именно WebP: AVIF выигрывает в байтах, но декодируется дороже на слабом CPU и может ухудшить LCP при меньшем весе. AVIF — только если замер на троттлинге показал выигрыш по LCP, а не по размеру файла.
- Шрифты локально, woff2, сабсет кириллицы, `font-display:swap`. Неиспользуемые начертания и семейства удаляем сразу.
- Сторонних origin в рантайме нет вообще: ни GSAP, ни шрифтов, ни аналитики. Нужна аналитика — со своего домена, после первого взаимодействия, в пределах бюджета JS. Гейт на сторонние origin исключений не делает.

## Производительность

- Блюр больше 8px в рантайме не считаем: запекаем в WebP. `filter: blur` на движущемся элементе запрещён.
- `mix-blend-mode` на слое размером в экран запрещён. Массовые частицы — один `<canvas>`, не DOM-узлы.
- `will-change` включается по фазе и снимается после неё. Статических объявлений в CSS быть не должно.
- DPR кэпим на 2. Canvas и тикеры на паузу за кадром и на скрытой вкладке.
- В тикере пишем только активные фазы: dirty-флаг на каждую, вне окна сеттеры молчат.
- `ScrollTrigger.refresh()` дебаунсится не меньше 200 мс и не вызывается на каждый кадр resize: пересчёт всех триггеров это layout-шторм.
- Экран приложения — обычный элемент в том же документе. Если iframe почему-то остаётся, то только `srcdoc`, не `document.write`.
- `prefers-reduced-motion`: сцена показывается статикой, ключевые кадры доступны без скролла.
- **Контент виден без JS.** Начальные состояния сцены ставит скрипт, а не CSS. `opacity: 0` и сдвиги, прописанные в стилях и снимаемые только скриптом, превращают одну ошибку JS на старом Safari в пустую страницу. Проверяется с отключённым JS перед каждым мержем.

## LITE

Флаг один, версия страницы по-прежнему одна, ветки живут внутри тех же модулей.

- Считается один раз при загрузке и замораживается. Переоценка на `resize` запрещена: поворот экрана не должен переключать ветки на живом скролле.
- Направление безопасное: **не смогли опознать устройство — значит `LITE`.** `deviceMemory` существует только в Chromium, в Safari он `undefined`, и условие «`deviceMemory` ≤ 4» там всегда ложно. Наивный детект выдал бы старому iPhone полную сцену.
- `prefers-reduced-motion` сильнее и проверяется первым: это статика, а не облегчённая сцена. Статика подразумевает `LITE`, обратное неверно.

```js
const cores = navigator.hardwareConcurrency;   // есть во всех живых браузерах
const mem   = navigator.deviceMemory;          // только Chromium

export const STATIC = matchMedia('(prefers-reduced-motion: reduce)').matches;

export const LITE = STATIC
  || navigator.connection?.saveData === true
  || innerWidth < 900
  || (typeof cores === 'number' ? cores <= 4 : true)
  || (typeof mem === 'number' && mem <= 4);
```

Отсутствие `hardwareConcurrency` трактуется как слабое устройство, отсутствие `deviceMemory` — нет: иначе под `LITE` уехал бы весь десктопный Safari.

- Что деградирует: без роя, без видео, влёт из 8 карточек вместо 20, без `blur` и `box-shadow` на движущихся слоях.
- Что не деградирует: хореография. Те же элементы, те же кривые, та же последовательность — только дешевле. На нормальном устройстве сцена идёт без изъятий.
- Ветки — на входе в фазу, а не внутри покадрового цикла: фаза включается или пропускается целиком. Это и меньше кода под тестирование.

## Сцена

- Тайминги живут только в `src/scene/phases.js`. Число фазы в любом другом файле — баг. Окна не пересекаются, кроме помеченных `overlap: true` с причиной.
- Порядок внутри сцены: корпус доехал, сменился контент в экране, вышел текст. Смена фона и смена групп — только в пустых паузах между надписями.
- Таймлайн надписей играется `capTl.time(p)`, не `progress()`: длину держит настоящий твин, а не пустой `set()`.
- Один моушен-язык: база `cubic-bezier(.6,0,.4,1)` 300ms, вход `expo.out`, уход `power2.inOut`. Новый изинг — с объяснением зачем.
- Менять тайминги — значит приложить пересчитанную карту окон, проверку на пересечения и обновлённый `docs/baseline/`.

## Команды

Дев-сервер `npm run dev`. Сборка `npm run build` → `dist/`, проверка сборки `npm run preview`. Бюджет `npm run budget` (`node scripts/budget.mjs`, лимиты в `budget.json`). Карта фаз `npm run phases:check` — падает на пересечении окон. Lighthouse отдельной командой и только по решению, из-за веса зависимостей.

## Деплой

Ассеты с фингерпринтом от Vite отдаются с `Cache-Control: public, max-age=31536000, immutable`, `index.html` — без кэша. Повторный визит не должен снова качать те же 900 КБ.
