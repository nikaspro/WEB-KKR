# AGENTS.md

Проект — предрелизный лендинг «Путешествовать — легко». Статика, Vite, ванильный JavaScript, CSS и GSAP из npm.

## Цель

Довести текущую сцену до стабильного релиза без разрастания кода.

Порядок приоритетов:

1. Сохранить утверждённый визуал и хореографию.
2. Устранить ошибки, дёрганье, битые состояния и проблемы адаптива.
3. Уменьшать код, число запросов, объём ресурсов и работу главного потока.
4. Не добавлять функции, которых нет в текущем предрелизе.

## Компактность кода

- Монолитные HTML-файлы запрещены. HTML содержит разметку, CSS и JS лежат отдельно.
- Не добавлять новую реализацию, пока не проверены существующие функции, стили и ассеты.
- Новая строка должна решать видимую проблему. Комментарии объясняют только неочевидное решение.
- Дубли селекторов, констант, медиазапросов и одинаковых обработчиков объединять.
- Не держать две реализации одной сцены. `legacy/rd-hero-v4.html` — только совместимый переход на корневую версию.
- Ориентиры для одного файла: HTML до 500 строк, JS/CSS до 2000 строк. Превышение требует упрощения или осмысленного разбиения, а не косметического переноса строк.
- Не считать минификацию исходников оптимизацией. Исходники остаются читаемыми, production-сборку минифицирует Vite.
- Не вводить React, Vue, TypeScript, SSR, CMS, роутер и новые runtime-зависимости.
- GSAP и ScrollTrigger импортируются из npm. Локальные vendor-копии не храним.
- Подробные правила подключения и использования GSAP находятся в `GSAP.md`.

## Структура

- `index.html` — единственная рабочая страница.
- `src/scene/scene.js` — логика и анимация сцены.
- `src/scene/phases.js` — окна и тайминги фаз.
- `src/styles/scene.css` — стили страницы.
- `public/assets/` — локальные медиа, шрифты и экран приложения.
- `legacy/` — только совместимость со старой ссылкой, не второй источник кода.

Если файл снова становится трудно просматривать целиком, сначала удалить мёртвый код и дубли. Разбивать на модули только по независимым зонам ответственности.

## Предрелизные ограничения

- Никаких внешних origin в рантайме: шрифты, GSAP и медиа только локально.
- Никаких `data:` длиннее 2 КБ. Изображения и SVG хранить файлами.
- Все изображения имеют `width`, `height`; всё вне первого экрана — `loading="lazy"`.
- Видео: `preload="none"`, `poster`, muted, без автозагрузки до попадания в сцену.
- Контент должен оставаться видимым без JavaScript.
- `prefers-reduced-motion` показывает статичную понятную страницу.
- Не использовать полноэкранный `mix-blend-mode`, движущийся `filter: blur()` и постоянный `will-change` в CSS.
- `ScrollTrigger.refresh()` не вызывать в покадровом цикле.
- Любая новая зависимость или изменение лимитов в `budget.json` — только по прямому решению владельца.

## Анимация

- Оптимизировать стоимость эффекта, не менять утверждённый результат.
- Без согласования можно переводить движение на `transform`/`opacity`, объединять rAF-циклы, кэшировать DOM и отключать работу вне активной фазы.
- Тайминги, easing, stagger, порядок и число элементов без согласования не менять.
- Фазы не должны пересекаться, кроме явно разрешённых overlap в `src/scene/phases.js`.
- Один расчёт состояния на кадр: чтение DOM перед записью, без чередования layout read/write.

## Рабочий порядок

1. Проверить `git status` и затрагивать только файлы задачи.
2. Делать точечный патч; не переписывать рабочую сцену без необходимости.
3. После изменения выполнить:

   - `node --check` для изменённого JS;
   - `npm run build`;
   - `npm run budget`;
   - `npm run phases:check` при изменении сцены;
   - `npm run legacy:check` при изменении совместимой страницы или embedded-экрана.

4. Перед публикацией проверить desktop, mobile, reduced motion, консоль и страницу без JS.

## Ответ после задачи

Кратко указать:

- что изменилось;
- как проверить;
- что не удалось проверить;
- вес JS, критического пути и страницы целиком;
- изменился ли визуал или хореография.

Без прямого запроса не выполнять force push, не менять `main`, не удалять пользовательские данные и не добавлять новые функции.
