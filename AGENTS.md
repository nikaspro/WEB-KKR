# AGENTS.md

Проект — предрелизный лендинг «Путешествовать — легко»: Vite, ванильный JavaScript, CSS и GSAP из npm.

## Приоритеты

1. Сохранить утверждённые дизайн, контент, адаптив и хореографию.
2. Устранить ошибки, битые состояния и проблемы производительности.
3. Сокращать дубли, лишние запросы и работу главного потока.
4. Не добавлять функции, которых нет в текущем сценарии.

## Структура и организация кода

- `index.html` — единственная рабочая страница и содержит только разметку.
- Стили находятся в `src/styles/`, логика и анимации — в `src/scene/`.
- `src/scene/phases.js` — единый источник окон и таймингов фаз.
- `public/assets/` — локальные шрифты, медиа и embedded-экран.
- `legacy/rd-hero-v4.html` — только совместимый переход на корневую страницу, не вторая реализация.
- Ориентиры для одного файла: HTML до 500 строк, JS до 2000 строк, CSS до 2000 строк.
- При превышении ориентира сначала удалить мёртвый код, дубли и лишние условия. Если файл всё ещё слишком большой — разделить его по независимым зонам ответственности.
- Не дробить код на множество маленьких файлов без практической необходимости.
- Не создавать вторую реализацию существующего блока и не держать старую и новую версии одной функции, сцены или анимации одновременно.
- Не добавлять временные файлы, копии, архивы, build-артефакты и неиспользуемые ассеты.
- Исходники остаются читаемыми; минификацию выполняет production-сборка Vite.
- Не вводить React, Vue, TypeScript, SSR, CMS, роутер или новую архитектуру без прямой необходимости.

## Переиспользование

- До реализации проверить существующие компоненты, функции, стили, селекторы, переменные, GSAP timelines и ассеты.
- Не переизобретать уже существующую механику.
- Для новых секций переиспользовать имеющиеся паттерны адаптива, состояний, easing и управления скроллом.
- Если нужный эффект уже есть, переиспользовать или аккуратно расширить существующую анимацию.
- Принципиально новую анимацию создавать только по прямому запросу владельца.
- Не заменять рабочую реализацию другой библиотекой или архитектурой без необходимости.

## Предрелизный режим

- Новая строка кода должна решать конкретную видимую проблему или обязательную предрелизную проверку.
- Не добавлять функции, которых нет в текущем сценарии.
- В рамках технической оптимизации не менять текст, размеры, позиции, пропорции, цвета, easing, stagger, тайминги и порядок элементов.
- Все интерактивные элементы должны иметь корректные состояния и не оставаться необозначенными визуальными заглушками.
- Все внутренние ссылки должны вести к существующим секциям.
- В консоли не должно быть ошибок и предупреждений проекта.
- Страница должна работать на desktop, mobile, нестандартных соотношениях сторон, с `prefers-reduced-motion` и на базовом уровне без JavaScript.
- Никаких внешних runtime-ресурсов: шрифты, GSAP и медиа только локальные.
- Не добавлять зависимости без прямого согласования.
- Не повышать лимиты `budget.json` ради прохождения проверки.

## Ассеты и производительность

- Никаких `data:` длиннее 2 КБ; изображения и SVG хранить отдельными файлами.
- Все изображения имеют `width` и `height`; контент вне первого экрана использует `loading="lazy"`.
- Видео: `preload="none"`, `poster`, muted и без загрузки до входа в сцену.
- Не использовать полноэкранный `mix-blend-mode`, движущийся `filter: blur()` и постоянный `will-change` в CSS.
- Один кадр: проверить активность, прочитать DOM, рассчитать состояние, затем записать свойства. Не чередовать layout read/write.
- Кэшировать DOM и отключать работу вне активной фазы.

## GSAP и скролл

- GSAP и ScrollTrigger импортируются из npm и регистрируются один раз. Подробные правила — в `GSAP.md`.
- Не менять easing, duration, stagger, точки срабатывания, порядок и число элементов без прямого запроса.
- Не создавать новую анимацию, если эффект уже реализован существующим timeline.
- Фазы не пересекаются, кроме явно разрешённых overlap в `src/scene/phases.js`.
- Использовать общий `gsap.ticker`; не создавать параллельные покадровые циклы без необходимости.
- `ScrollTrigger.refresh()` не вызывать в scroll/resize без debounce и никогда не вызывать в покадровом цикле.
- `prefers-reduced-motion` показывает понятное статичное состояние без scrub-анимации.

## Рабочий порядок

1. Прочитать `AGENTS.md` и `GSAP.md`, проверить `git status` и существующую реализацию.
2. Затрагивать только файлы задачи и делать минимальный осмысленный патч.
3. Для изменённого JS выполнить `node --check <file>`.
4. Выполнить `npm run check`: build, budget, phases и legacy.
5. Перед публикацией проверить desktop, mobile, нестандартный viewport, reduced motion, консоль и страницу без JS.
6. Убедиться, что GitHub Pages открывается со всеми локальными ассетами.

## Итоговый отчёт

Указать:

- изменённые файлы и результат проверок;
- исправленные ссылки, удалённые дубли и оставшиеся продуктовые заглушки;
- превышения ориентиров по строкам и безопасную схему будущего разделения;
- вес JS, критического пути и страницы целиком;
- что не удалось проверить;
- изменились ли визуал или хореография.

Без прямого запроса не выполнять force push, не менять `main`, не удалять пользовательские данные и не добавлять функции.
