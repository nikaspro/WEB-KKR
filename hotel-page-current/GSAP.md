# GSAP в проекте

Единый источник анимации — npm-пакет `gsap`. CDN, локальные vendor-копии и собственные обёртки не используются.

## Подключение

GSAP подключается один раз в точке входа `src/scene/scene.js`:

```js
import { gsap } from 'gsap';
import { ScrollTrigger } from 'gsap/ScrollTrigger';

gsap.registerPlugin(ScrollTrigger);
```

Полный пакет GSAP установлен через npm, но в production-бандл попадают только используемые модули. Импорт из `gsap/all` не нужен: он делает источник менее явным и упрощает случайное подключение лишних плагинов.

`ScrollTrigger` — плагин из того же пакета GSAP, а не отдельная библиотека. Регистрировать его нужно один раз до создания таймлайнов.

## Правила проекта

- Один экземпляр GSAP и одна регистрация каждого используемого плагина.
- Новые плагины подключать только при реальной необходимости и после замера production-бандла.
- Последовательные анимации собирать в `gsap.timeline()`, а не в цепочки таймеров.
- В покадровых сценах использовать общий `gsap.ticker`; не создавать параллельные `requestAnimationFrame`-циклы.
- Частые записи свойств делать через заранее созданный `gsap.quickSetter()`.
- В горячем цикле не искать DOM-элементы и не создавать новые tween-объекты.
- Для движения использовать `x`, `y`, `scale`, `rotation` и `opacity`. Не анимировать layout-свойства без необходимости.
- Для событийных tween указывать подходящий `overwrite`, чтобы повторные события не накапливали конкурирующие анимации.
- Начальное скрытие контента ставить из JS через `gsap.set()`. Без JavaScript страница должна оставаться видимой.
- При `prefers-reduced-motion` показывать понятное статичное состояние без scrub-анимации.

## ScrollTrigger

- Тайминги сцены хранятся в `src/scene/phases.js`; не дублировать их в обработчиках.
- `ScrollTrigger.refresh()` вызывать только после изменения геометрии или декодирования важного медиа.
- Не вызывать `refresh()` в `scroll`, `resize` без debounce или в покадровом цикле.
- Для scrub-сцен задавать явные `start`, `end` и `invalidateOnRefresh`, если значения зависят от viewport.
- Не создавать несколько триггеров для одного эффекта, если его можно выразить одним таймлайном.
- При удалении динамической сцены останавливать её timeline/trigger и снимать слушатели.

## Производительность

Правильный порядок одного кадра:

1. Проверить, активна ли фаза.
2. Один раз прочитать необходимые размеры и прогресс.
3. Рассчитать состояние.
4. Записать свойства через кэшированные setter-функции.

Не чередовать чтение layout и запись стилей внутри одного цикла. Не создавать `querySelector`, массивы и строки CSS без необходимости на каждом кадре.

`will-change` не хранится постоянно в CSS. Если продвижение слоя действительно требуется, его нужно включать перед активной фазой и снимать после неё.

## Запрещено

- `<script>` с cdnjs, unpkg, jsDelivr или другим CDN;
- `public/vendor/gsap.min.js`, `ScrollTrigger.min.js` и их копии;
- одновременные импорты из `gsap`, `gsap/all` и локального файла;
- регистрация всех плагинов «на будущее»;
- собственная универсальная обёртка над `gsap.to()`, скрывающая параметры анимации;
- изменение easing, duration, stagger и точек срабатывания под видом оптимизации.

## Версия

Версию задают `package.json` и `package-lock.json`. Обновление выполняется только через npm и отдельным изменением, после которого обязательно сравниваются визуал и размер сборки.

Текущее установленное разрешение:

```text
gsap@3.15.0
```

## Проверка

```powershell
npm ls gsap --all
rg -n -i "gsap|ScrollTrigger|cdnjs|unpkg|jsdelivr" -g "!node_modules/**" -g "!dist/**" .
node --check src/scene/scene.js
npm run build
npm run budget
npm run phases:check
npm run legacy:check
```

Готовое состояние:

- `npm ls` показывает один экземпляр GSAP;
- в исходниках один npm-импорт и одна регистрация ScrollTrigger;
- vendor-файлов и CDN-подключений нет;
- production-сборка и бюджет проходят;
- визуал, тайминги и хореография не изменились.
